METHODS IMPLEMENTED
================================================================================

OVERRIDE (1 method):
  make_accrual_jv_entry(submitted_salary_slips)
    - Main orchestration method
    - Creates JV with party details for Receivable/Payable accounts
    - Maintains standard reference fields for cancellation support
    - Calculates payable amount correctly

DETECTION METHODS (4 methods):
  get_account_type(account_name)
    - Fetches and caches account type
    - Returns account type string or empty string
    
  get_salary_components_by_account_type()
    - Classifies components by their account types
    - Returns dictionary grouped by account type
    - Deduplicates entries
    
  is_party_required_account(account_type)
    - Determines if account type needs party details
    - Returns True for Receivable/Payable/Bank accounts
    
  _add_component_to_dict(components_dict, processed_combinations, component_detail, salary_slip, field_type)
    - Helper method for deduplication
    - Adds components to classification dictionary

PROCESSING METHODS (2 methods):
  process_party_component(component_data)
    - Creates JV entry with party details
    - Sets party_type = "Employee" and party = employee_id
    - Returns list with entry dictionary
    
  process_standard_component(component_data)
    - Creates standard JV entry without party
    - For Expense, Income, and other accounts
    - Returns list with entry dictionary

UTILITY METHODS (1 method):
  validate_party_details(party_type, party)
    - Validates party information before JV creation
    - Checks employee exists in system
    - Returns boolean
